# 项目总方案 v0.1

## 体验承诺

玩家带领家庭与同伴走过旧约关键故事。每一章有可感知的处境、地理空间、人物关系与后果。玩家掌握准备、执行和照顾人的方式；经文明确的关键结果保留。目标是青少年及成人，单章约 20—35 分钟，首个样章 15—20 分钟。

## 四种玩法如何接续

| 故事处境 | 主要玩法 | 系统过渡 |
|---|---|---|
| 抵达陌生地 | 多角色探索、谈话、观察 | 发现泉水、牧道、木料与风险 |
| 资源紧缺 | 家庭生存、迁徙路线 | 水、载具、牲畜与体力改变可选路线 |
| 暂时驻扎 | 营地建设、劳动分工 | 建筑提供休息、储存与警戒能力 |
| 危机出现 | 暂停安排的小队行动或战斗 | 地形、队员能力、关系与物资改变解法 |

重复工作用角色职责和指令模板自动执行；玩家决定优先级、风险和何时调整。每一任务至少有一个可观察的前置信号、一个真实成本、一个后果和一个恢复路径。

## 战斗设计

战斗是剧情策略行动，不是全章常态。敌对行动包含警戒、躲避、驱离、护送、防卫和少量正面交战。首章用**野兽接近羊群**做教程冲突，此事件是明确标记的游戏虚构；玩家可部署侦察者或领队警戒驱离，未来版本增加绕行、火把、掩护与羊群撤离。当前实现只有简化的驱离判定，尚无战斗寻路、攻击动画或敌方 AI。

后续适合战斗的经文节点：创世记 14 章亚伯兰营救罗得；出埃及记 17 章亚玛力人；约书亚记、士师记、撒母耳记中的具体冲突。对经文中的暴力、规模和人物动机逐章审阅。玩家能改变准备、伤亡与资源后果，不能把经文明确的事件改写为相反结局。青少年目标要求可切换血腥表现，默认使用非写实反馈。

## 样章 15—20 分钟目标流程

| 时间 | 观察、决策与操作 | 反馈与后果 |
|---|---|---|
| 0—2 分 | 认识亚伯兰、撒莱、罗得和四名虚构队员，观察水、牧地、山脊 | 角色职责与地形差异在画面上可读 |
| 2—5 分 | 选队员、暂停排队列，派人取水、收木、观察牧道 | 角色走到目标，资源和体力改变；可中断改派 |
| 5—8 分 | 决定先搭遮蔽还是储水；安排运料 | 当晚休息和移动速度产生差异 |
| 8—11 分 | 山脊发现风险，安排警戒、绕行或驱离 | 羊群安全、队员疲劳与关系发生变化 |
| 11—15 分 | 牧人争执，与罗得谈话，决定分离前的资源处理 | 罗得先选方向，关系与后续资源留档 |
| 15—20 分 | 打包、选择安全路线、回顾营地结果 | 下一章获得不同起始条件与人物对白 |

当前系统原型仅实现上述动作的基础链与结局文本。运输路径、休息、绕行、打包和下一章承接尚未完成，不能按此表宣称已交付 20 分钟样章。

## 高影响决策记录

| 决策 | 选项 | 选择与原因 | 风险 |
|---|---|---|---|
| 3D 技术 | Unity WebGL；Godot Web；Three.js + React | Three.js + React：复用 Web/Capacitor，低安装门槛，数据与 UI 容易迭代 | 复杂寻路与动画需自建或增库；大型场景性能压力 |
| 战斗节奏 | 实时微操；回合制；实时加暂停 | 实时加暂停：与劳动指令共用队伍选择和队列 | 手机端指令 UI 容易拥挤 |
| 圣经自由度 | 完全分支；严格复述；固定主事件加可变过程 | 固定主事件加可变过程：保留经文事件，允许成本、关系、准备不同 | 玩家可能误认补充情节为经文 |
| 美术生产 | 全手工 3D；AI 直出贴图/模型；概念辅助加人工建模 | 概念辅助加人工建模与审核：统一轮廓、骨骼和材质 | 人力投入较高 |

## 交付门槛

1. 先审分镜、经文边界和视觉规格，再扩大内容生产。
2. 做可独立重玩的 15—20 分钟切片，验证正常入口、重复操作、中断恢复、手机触控与低端设备帧率。
3. 产出 Web 构建和 Android 调试包；iOS 工程同步并在 macOS 编译验证。
4. 每次发布附上已实现、已验证、未验证三张清单。

## DeepSeek 协作规则

可让 DeepSeek 生成**边界明确的基础代码**：角色数据类型、寻路适配器、内容 JSON 校验器、存档迁移器、UI 组件初稿。每项任务给出输入/输出接口、禁止改动范围和验收用例；我负责合并、测试、性能与叙事审核。项目不会依赖 DeepSeek 私有服务运行；目前未连接 DeepSeek API，因此尚无代码由它生成。
