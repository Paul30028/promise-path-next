# 技术架构与验证 v0.1

## 当前结构

Web 使用 Vite + React + TypeScript；3D 使用 Three.js / React Three Fiber；移动端拟用 Capacitor 包装同一 Web 游戏。此选择适合小地图、少量角色和高频 UI 迭代。若战斗规模、动画或场景体量明显增长，需重新对比 Godot/Unity 的生产效率。

`Game` 是纯数据快照。`tick` 处理角色指令队列及资源结算。`World` 只渲染和上报点击；`App` 负责 UI 与决策。保存为本地 JSON，版本字段为 1。当前恢复只做基本字段检查，正式版要加 schema 校验、迁移表、原子写入与备份槽。

## 下一步系统接口

| 模块 | 数据与接口 | 当前状态 |
|---|---|
| 角色/移动 | actor id、位置、体力、负重、命令队列 | 直线移动已实现；避障/寻路未实现 |
| 镜头与选人 | 固定俯视、多人选择、点击地面 | 已实现；框选与拖动镜头未实现 |
| 任务与对话 | 章节 id、节点、条件、效果、经文标签 | 单章硬编码；需数据驱动 |
| 资源与建设 | 数量、输入成本、产出 | 水/木/帐棚已实现；库存位置/运输未实现 |
| 战斗/卡牌 | 威胁发现、情境手牌、队列、防卫后果 | 三张固定战术卡；抽牌构筑、敌 AI、站位和多回合交战未实现 |
| 关系与状态 | 信任、体力 | 基础数值；疲劳恢复/长期关系未实现 |
| 内容加载 | glTF、贴图、动画、章数据 | 程序几何体；需清单与预加载 |
| 存档 | 版本 1、本地自动保存 | 基础恢复；迁移/坏档修复未实现 |

正式内容格式建议 `chapter.json` → `level.json`，角色、地点、任务、对白、道具用稳定 id 相互引用；每事件包含 `sourceRefs`、`adaptationKind`、`preconditions`、`effects`。加载时用 schema 校验，运行时不允许内容脚本直接任意修改状态。

## 性能初始预算

目标设备：近三年中端 Android（约 6 GB RAM）、iPhone 12 级、主流桌面 Chrome。目标 30 FPS 移动端、60 FPS 桌面；移动端首屏交互 < 8 秒，场景下载 < 25 MB 压缩，GPU 纹理常驻 < 64 MB，单场景 draw calls < 150。当前 JS 压缩前约 1.14 MB，尚无实机帧率、内存和下载测量。以上是预算，不能写成达标结果。

## 验收用例

1. 首次进入：能看到三维地图、人物与任务说明。
2. 重复操作：连续排水/木/施工，材料不足时不扣负数。
3. 暂停：队员停止，队列可清除，恢复后继续。
4. 中断：刷新后位置、资源、任务、队列保留。
5. 剧情：两种准备方式都保留罗得先选方向和双方分开的经文结果。
6. 异常：损坏或旧版本存档回退到新游戏；存储被拒绝给出提示。
7. 手机：触控选人/地面移动/按钮均可达；测量帧率和内存。
