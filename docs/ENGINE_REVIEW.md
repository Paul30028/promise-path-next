# 引擎选择阶段记录

当前样章使用 Vite、React、Three.js 与 Capacitor，已有 Web 运行版、Android 调试包、iOS 工程及可重复生成的 glTF 模型。用户提供了 Godot、Redot、GDevelop、Defold 和若干开源战术/管理项目，作为后续评审输入。仓库链接、星数和许可证在采用任何第三方代码前须重新核验；本阶段未引入这些项目的代码或资产。

| 方案 | 当前体验与制作 | Web/移动端 | 主要代价 |
|---|---|---|---|
| 继续 Three.js + Capacitor | 界面与样章已可运行；React 适合快速迭代双语 UI | 当前已构建 Web、Android；iOS 工程待实测 | 更复杂的动画、导航、关卡编辑和性能工具需要自行建立 |
| 迁移 Godot 4 | 更完整的游戏编辑器、动画与场景工作流 | 支持 Web 与移动端导出，实际设备表现仍须验证 | 现有 UI、状态、存档、输入及构建管线需重写；Web 包体与移动端表现要重新测量 |
| 混合方案 | Web 样章继续推进，另做 Godot 技术样片 | 可用同一 glTF 资产对照 | 两条管线暂时增加维护量，但能用实际数据决定迁移 |

**当前决定：**保留现有工程完成第一阶段可玩样章；在需要骨骼动画、复杂寻路和内容编辑器之前，做一张相同场景的 Godot 技术样片，对照 Web 首屏时间、Android 帧率/内存、glTF 导入、暂停指令和开发工时，再决定是否整体迁移。这是阶段性选择，不把引擎迁移作为本轮界面重做的隐性前提。
