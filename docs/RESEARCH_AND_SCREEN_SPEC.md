## 一、 剧情设计研究：如何解决“圣经结局剧透”并做出真正的叙事重量？

传统宗教/历史游戏最大的通病是：**玩家早就知道结局（如罗得必选约旦河平原、亚伯兰必得应许），因此觉得自己的选择毫无意义。**

通过研究四款公认的“既定历史/宿命叙事策略”神作，我们提炼出可直接复用的 **三大叙事机制**：

| 参考名作 | 它们如何处理“不可改变的宏观历史”？ | 玩家真正掌控的“自由度（Agency）” | 对《应许之路》第一关（创 13）的直接改造 |
| :--- | :--- | :--- | :--- |
| ***Pentiment***<br>（黑曜石历史叙事） | 大时代宗教与社会变迁必然发生，但**玩家决定谁背锅、谁受苦、以及隔代余波** | 有限时间槽分配（每天只能去几个地方，来不及救所有人） | 加入**「日落前有限行动窗口」**：你来不及同时照顾所有人，必须决定优先稳固主帐、还是优先安抚罗得或守望山脊 |
| ***The Banner Saga***<br>（旗帜的传说） | 世界末日与诸神黄昏不可逆转 | **照管车队补给与同伴生死**：主角团不死，但同行普通队员会因你的调度失误永久受伤/离队 | 主线（亚伯兰与撒莱）保持经文定数；**随行同伴（以利以谢、夏甲、乌珥）承担真实伤疲代价**，并直接影响第二关《但地夜袭》可用战力 |
| ***Frostpunk***<br>（冰汽时代） | 大寒潮降温时间表绝对固定 | **道德与资源的交易（Faustian Bargain）**：为了熬过寒潮，你愿付出什么代价？ | 在分离前，你可以通过牺牲**自己的宝贵饮水（共饮上泉）**或**木料（赠材助迁）**来保全羊群与两家和睦 |
| ***Six Ages***<br>（六纪元氏族） | 氏族必然随历史纪元迁徙更替 | **仪式、传统与家族记忆铭刻**：决定家族以何种品格面对宿命 | 每章结束将关键准备与同伴命运刻入**「家族泥板档案」**，下一关NPC对白与初始物资会真实引用上一关的抉择 |

### 剧情设计结论
- **不要做“文字小说式播片弹窗”**，而是把剧情压力做成**「时间窗口 + 资源两难 + 同伴命运」**。
- 第一关必须有 **3 个动态叙事节点**（而非最后弹一个对话框）：① 抵达营地时发现**罗得的羊群正在挤占草场**（空间张力）；② 黄昏时**山脊狼群逼近**（消耗抉择：烧木料做火把 vs 耗饮水转移羊群）；③ 入夜前**牧人争执临界点**（用你省下来的水或木料，换取两家体面分离）。

## 二、 游戏模式研究：如何平衡“商业留存”与“策略深度”？

我们对比了三款代表不同商业化路径的策略名作在 **单局时长、镜头控制与核心循环** 上的真实表现：

| 维度 | *Whiteout Survival*（无尽冬日） | *Thronefall*（王权陨落） | *Kingdom Two Crowns* |
| :--- | :--- | :--- | :--- |
| **商业成绩** | 手游累计 **\$30 亿+**，2025年单月最高 \$1.82 亿 | Steam **170 万份**，**\$1,100 万+**，好评率 **96%** | 跨平台长青买断精品（PC/NS/Mobile） |
| **核心循环** | 中心圣火基建 + 计时器收菜 + 4X远征 | **白昼极简建营（经济）↔ 夜晚率队防卫（战斗）** | 横向扩张营地 + 夜晚防卫贪婪怪物 |
| **单局时长** | 2–5 分钟高频碎片 | **5–15 分钟**（极度契合手机通勤与睡前节奏） | 20–45 分钟（手机端易中途被打断） |
| **优点与隐患** | 吸金极强但重度数值逼氪，易引基督徒家庭反感 | **零废话、极高心流与重玩性**，但纯塔防缺人物故事 | 氛围极佳，但横版卷轴在手机竖屏体验差 |

### 游戏模式最终定型：**「*Thronefall* 昼夜双相节奏 × *Whiteout* 中心祭坛经营 × 定格小队微操」**
1. **单关时长压缩到 6–12 分钟（支持随时断点续玩）**：比原计划的 20–35 分钟更符合现代手机玩家习惯，一局内包含 **「2 个白昼建设轮 + 1 个夜晚危机防卫轮 + 1 次经文历史抉择」**。
2. **白昼阶段（经营与分工）**：围绕中央**十二石立约祭坛**，点选角色去山泉汲水、收木、把右上角空木架搭成游牧帐棚、在主帐歇息回体，同时压制**草场拥挤摩擦条**。
3. **夜晚/危机阶段（定格战术与手牌）**：夜幕降临或侦察山脊触发双狼逼近，游戏进入**定格规划**，玩家使用场上角色站位 + **3 张与营地物资挂钩的情境手牌**化解危机（零血腥、火把与牧杖驱离）。

## 三、 手机屏幕设置与人机工学（UX）专项研究报告

结合 **2024–2025 移动策略游戏 UX 研究** 与我们在本地实测生成的 `844×390` 横屏 / `390×844` 竖屏裁切模拟图，手机端屏幕设置存在以下硬性科学规律：

### 1. 横屏 vs 竖屏的商业与体验权衡
- **竖屏（Portrait, `390×844`）**：**赢在次日留存（D1 Retention）与单手零门槛**。通勤/碎片时间单手即可点开游玩，但水平视野极窄（如果锁死镜头，左右两侧的山泉与羊群会被全部裁出屏幕外）。
- **横屏（Landscape, `844×390`）**：**赢在 7–30 日长留存（D7–D30）与战术全局观**。但强制双手横握会带来轻微的启动门槛；且手机横屏高度只有 `390px`，如果上下都放 HUD 条，中间有效视野会被压成 `3.37:1` 的超扁条，上下地标全被裁掉。

### 2. 手机端「拇指热区（Thumb-Zone）」黄金法则
```text
┌─────────────────────────────────────┐
│  顶部死区（单手难以触及）：          │ ◀ 仅放只读信息：资源条、昼夜进度、目标
│  [ 💧水  🪵木  ⛺帐  🐑羊  ⚡摩擦 ]  │
├─────────────────────────────────────┤
│                                     │
│  中部黄金视野（点击角色 / 点击地面） │ ◀ 35° 等距沙盘：保留 >= 62% 画面面积
│                                     │
├─────────────────────────────────────┤
│  底部拇指舒适弧区（主操作区）：      │ ◀ 全部高频交互按钮 >= 44×44 CSS px：
│  [ 角色头像横滑 ] [ 行动/手牌 ] [▶执行]│   定格/执行、清队列、行动指令、战术手牌
└─────────────────────────────────────┘
```
- **铁律**：绝不允许把高频操作按钮（如“执行指令”、“返回”、“建造确认”）放在屏幕**左上角或右上角**，必须全部收拢在**底部或右侧拇指舒适弧区**。

### 3. 本项目双端自适应屏幕规范（正式工程执行标准）

| 视口模式 | 布局架构（Layout） | 摄像机与缩放策略（Camera & Zoom） | 触控与安全区规范 |
| :--- | :--- | :--- | :--- |
| **桌面宽屏**<br>（`>= 1024px`） | **全屏沙盘 + 四角轻量化悬浮 HUD**（顶部章节/资源，左侧角色微章，底部手牌与执行） | 固定全局俯视（FOV `34°`），全营地 6 大区域一屏尽收眼底 | 鼠标点击选人/地面，悬停显示提示与曲线轨迹 |
| **手机横屏**<br>（`844×390` 基准） | **左侧 `65%` 纯净 3D 沙盘（约 `558×390`，完美贴合 `3:2` 底图比例）+ 右侧 `286px` 紧凑指令坞**（绝不在上下叠满 HUD 条） | FOV `30°`，可轻微平移观察边缘；顶部/底部只留 24px 极细安全边距 | 所有可点击按钮 `>= 44×44 CSS px`，队伍头像支持横向滚动吸附 |
| **手机竖屏**<br>（`390×844` 基准） | **上方 `52%` 场景视口（`390×440`）+ 下方 `48%` 拇指操作区**（队伍横排 + 行动/手牌 + 固定底部执行栏） | **强制开启「镜头智能跟随 + 单指拖动平移 + 快捷地标定位钮」**：点选谁镜头平滑移向谁，并在场景下缘提供「泉眼 / 祭坛 / 羊群」一键飞镜胶囊 | 适配 iOS/Android 刘海屏与底部 Home Bar（`env(safe-area-inset-bottom)`），状态栏深色沉浸 |
