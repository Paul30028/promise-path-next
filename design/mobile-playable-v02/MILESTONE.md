# 渡口试玩 0.2 · 内部开发构建

目标是检验玩家能否从牧人口中了解到路线风险，带合适的工具，并在交付时解释结果。采用横屏固定镜头、第二版中英文画面与 Android WebView。渡口事件为原创玩法试案。

## 构建与交付

启动 Promise-Path.html 可离线试玩。手机安装 Promise-Path-debug.apk。运行 python build.py 生成同内容的网页，设置 JAVA_HOME、ANDROID_HOME 后运行 python build.py --apk。依赖 Android 35 平台、35.0.0 构建工具和本机 Android debug keystore。设计图嵌入发行文件，本地运行无需联网。

## 已验收

Android 34 x86_64 模拟器：覆盖安装、横屏冷启动、NPC 消息、羊毛换牧绳、山脊护送、6 只羊和 2 包货交付、领取盐袋。强制停止并重新进入显示已交付记录。进入方舟独立试章，调入一名储粮人员，产出船体 2 段和储粮 4 担。APK 通过签名校验。

## 后续里程碑

1. 内部试玩：在中端 Android 真机核对热区、字号、WebView 兼容性及长时间切后台；使用同一地图比较换装与保留羊毛两种决定。记录误点和玩家是否主动重走。
2. 垂直切片：以试玩结果调节路线成本。把寻回承诺做成可完成的下一站，增加人物动作与事件反馈，量测完整章节时长。
3. 内容与发布：经文和历史复核、双语校对、资产权利归档、坏档恢复与发行签名。是否扩大到其他章节由样章的实机表现决定。
