# `/prototype` — Antigravity 游戏工作室原型工作流

当用户输入 `/prototype <游戏点子或章节需求>` 时，严格按以下四个阶段推进，不得跳步：

## 阶段一：核心玩法与美术边界对齐（Ask 3–4 Targeted Questions）
1. 结合市场调研数据与项目定位，向用户提出 **3–4 个高价值选择题或决策点**（使用 `ask_question` 工具或清晰列表）：
   - **核心循环与胜负手**：本关/本原型的 30 秒核心操作是什么？（如：中心祭坛基建、昼夜防卫、定格路线规划、情境手牌抉择）
   - **美术与时代风貌**：采用哪一历史时期的视觉符号？（严格执行去阿拉伯化、忠于旧约古希伯来与地中海黎凡特考据 + 2.5头身商业化 Q 版手办风）
   - **数值与状态边界**：需要哪些独立配置项写入 `src/config.ts`？
2. 等待用户确认回答后再进入阶段二。

## 阶段二：生成一页纸立项简报（One-Page `design/game-brief.md` & Codex Concept Art）
1. 在 `design/game-brief.md` 中编写结构化的一页纸设计简报，包含：
   - **一句话核心体验（Elevator Pitch）与商业对标数据**
   - **核心状态机与 `src/config.ts` 数据结构表**
   - **角色分工表与经文/历史依据索引**
   - **15 分钟心流时间轴（0–3m / 3–8m / 8–15m）**
2. 如需配套全新视觉样图或角色立绘，调用 `codex`（内置 `imagegen`）生成高清设定板并嵌入简报。
3. 暂停并请求用户确认简报（Approval Gate）。

## 阶段三：模块化编码与可运行原型实现（Data-Driven Prototype Implementation）
1. 将所有数值、坐标、建筑成本、角色专长与卡牌配置抽离至 `src/config.ts`。
2. 实现/更新状态逻辑 `src/game.ts`、3D/2.5D 场景 `src/World.tsx` 与响应式双语界面 `src/App.tsx`。
3. 运行 `npm run build` 或 `npm run check` 确保零编译与类型错误。

## 阶段四：浏览器实机视觉自检与验收报告（Browser Visual Verification & Report）
1. 启动本地服务并通过浏览器子代理（或截图工具）打开实机画面，采集桌面横屏与移动竖屏运行截图。
2. 逐项核验：
   - 画面与 UI 无重叠、无穿模、无空白破图；
   - 角色移动、转向、2.5D 骨骼变形动画与交互反馈正常；
   - 本地存档与刷新恢复正常。
3. 输出包含**「已实现清单、已验证截图、待扩展项」**的正式验收报告。
